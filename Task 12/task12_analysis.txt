TASK 12 EVIDENCE REPORT

A. Impact Analysis
------------------
Original:
- 16-bit unsigned meter register.
- Readings expressed in units/kWh.
- Tariff values compiled into #define constants.
- Fixed slab calculation.

Changed:
- Smart meters send Wh readings every 15 minutes.
- 35,040 readings per house per year.
- 18:00–22:00 peak period has a 20% surcharge.
- Tariff values must be changed without recompilation.

16-bit capacity:
65535 Wh = 65.535 kWh.

Example capacity-to-days calculation:
At 10 kWh/day:
65.535 / 10 = 6.5535 days.

The exact number of days varies with household consumption, but the calculation demonstrates that a
16-bit Wh counter has a small energy capacity compared with annual use.

Annual worst-case sum using the maximum 16-bit interval value:
35040 × 65535 = 2,296,346,400 Wh.
This exceeds signed 32-bit INT_MAX = 2,147,483,647.

B. Original Design Evaluation
-----------------------------
Retain:
- integer paise representation,
- slab-based billing concept,
- validation,
- fixed-size arithmetic where the range is known.

Modify:
- meter/energy types,
- tariff storage,
- billing engine.

Redesign:
- runtime tariff structure,
- time-of-day engine,
- 64-bit Wh accumulation.

C. Revised Design
-----------------
Meter and annual energy totals: uint64_t.
Tariff: runtime Tariff structure loaded from tariff.conf.
Peak rule: 18:00 inclusive through 21:45 interval start; 22:00 is normal.
Money: paise as uint64_t.
Time complexity: O(N) for N readings.
Extra memory: O(1) with respect to N in the streaming implementation.

D. Evidence-Based Defence
-------------------------
1. 16-bit Wh capacity is only 65.535 kWh.
2. 35,040 intervals/year greatly increases the number of readings.
3. Worst-case annual accumulation shown above exceeds signed 32-bit int.
4. 64-bit integer arithmetic provides substantial headroom.
5. Runtime configuration satisfies the no-recompile requirement.
6. Time-of-day evaluation is constant-time per interval.
7. Integer monetary arithmetic preserves exact paise representation.

Runtime configuration complexity:
If t tariff values are loaded at startup:
- startup parsing time: O(t)
- tariff storage: O(t)
- each billing interval remains O(1)

This startup cost is small compared with recompiling and redistributing the application after each
tariff revision.
